## 三、技能池拖拽 —— 左→右拖不动的真相

你描述的两个现象（**只能右拖到左**、**左边出现右边已有的技能**）其实是**同一个 bug**：

左池 `d.cands` **没有过滤掉已经带着的技能**。于是你把「左边那个其实已经带在身上的技能」
往右拖，代码执行的是「用这个技能替换它自己」→ 界面毫无变化，看起来就是"拖不过去"。
（右→左能生效，是因为"卸下"走的是另一条分支。）

**修法**：左池改为 `d.cands.filter(id => pet.moves.indexOf(id) < 0)`。
**一处修复同时解决两个问题** ✅

**实测（v82-pool，6/6）**：

| 检查 | 结果 |
|---|---|
| 左池与右边是否有重叠 | **0 个**（修复前会混着已带的）✅ |
| 左 → 右（换上） | ✅ 寄生种子成功替换掉「撞击」 |
| 右 → 左（卸下） | ✅ 4 个变 3 个 |
| 换完刷新后 | 仍无重叠 ✅ |
| 计数文案 | 也改成按过滤后的数量显示 ✅ |

## 六、本批新增的坑

90. **把「标志位」当成了「编号」**：我给 SPECIES 注入体重时用了 `"pk":N` 当图鉴号，
   而 `pk` 其实是「这是宝可梦（而非洛克宠）」的布尔标志（值恒为 1）——
   结果 **1025 只全被注成了妙蛙种子的 6.9kg**。**教训**：注入数据前先**打印几个已知条目**核对
   （卡比兽应该是 460kg，一眼就能看出错），别只看"注入了多少处"这种计数。
91. **两个看似无关的 bug 往往是同一个根**：你说的"左边拖不到右边"和"左边出现右边已有的技能"，
   都是因为左池没做过滤 —— 修一处，两个现象同时消失。**教训**：先把现象归到一起找共同原因，
   再决定要不要分头修。
92. **官方数据里混着"版本特有"的说明**：PokéAPI 的中文描述里有 68 条是「无法使用这个招式」，
   那是**删招世代**的文案，不是招式效果。**教训**：数据源是"多版本混合"时，
   要留意这类版本相关文案（本项目还有一处同类：`min_turns` 对状态类招式其实表示持续回合）。
