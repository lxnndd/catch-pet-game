## 一、招式附加效果表：从「手工 64 条」换成「官方数据生成 214 条」

**旧做法**：`MOVE_FX` 是当初手工配的 64 条，只能覆盖常见招，且与官方多有出入。
**新做法**：直接用 PokéAPI 的官方字段生成：

| 官方字段 | 含义 | 用到的招数 |
|---|---|---|
| `stat_changes` + `target` | 能力变化（`target=user` 判方向） | 109 |
| `meta.stat_chance` | 能力变化的触发概率 | 31 |
| `meta.ailment` / `ailment_chance` | 异常状态与概率 | 55 |
| `meta.healing` | 变化技回复比例 | 10 |
| `meta.drain` | 攻击招吸血比例 | 7 |
| `meta.crit_rate` | 高暴击招 | 19 |

**三条生成规则**：
1. **宝可梦招式一律以官方为准** —— 官方有效果就用官方；官方明确「无附加效果」的（如纯伤害类）就把旧手工效果清掉。
2. **官方「没建模」的独特机制保留旧配置**（`meta.category` 为 `unique` / `field-effect`，如聚气、睡觉、守住、白雾）—— 否则这些招会变成「放了没用」。
3. **洛克招式 PokéAPI 没有数据** → 保留原手工配置（10 条）。

生成后：**214 条**（官方 196 + 洛克 10 + 独特机制 8）。

## 二、能力等级补上「命中 / 闪避」两档

`STAGE_KEYS` 现在是 **8 档**：`攻击 / 防御 / 特攻 / 特防 / 速度 / 暴击 / 命中 / 闪避`

- `stLabel`、战斗状态条（`statusChips`）、长按浮层的显示名都同步了。
- 初始化收敛到 `stZero()` 一处，旧存档缺键自动补 0（只有四项/六项的老档也能读）。
- 相关招式归位：影子分身 → 闪避 +1、变小 → 闪避 +2、甜甜香气 → 对手闪避 −2、烟幕/磨爪 → 命中 ∓。

## 三、招式命中率真正生效（此前完全没用到）

**这是个被埋了很久的问题**：`MOVES` 里每个招都有 `acc`（命中率，官方值），但代码里**从未用它做过判定** —— 只在浮层文字里显示过。也就是说改之前**所有招式都是 100% 命中**。

现在按官方口径判定：

```
命中率 = 招式命中率 × 命中档修正 ÷ 闪避档修正      （上下限 15% ~ 100%）
```

判定放在出招最前面，**变化技同样要判命中**（金属音 85、催眠术 55 这些原来连判都不判）。

实测（烈火深渊，官方命中 50）：

| 条件 | 实测命中率 |
|---|---|
| 基准（无档位） | 54% |
| 自身 命中 +2 | **84%** |
| 对手 闪避 +2 | **32%** |
| 自身 命中 −2 | **37%** |
| 命中 100 的招 | 100% |

> 📌 **注意**：从现在起招式**会打空了**（这是官方机制）。如果你觉得打空太影响手感，`applyMove` 里那行 `clamp(..., 0.15, 1)` 的算法可以直接加一个整体系数调高命中，说一声即可。

## 四、攻击招的官方附加效果开始生效

原来 `fxOf()` **只在变化技分支被调用**，所以攻击招的附加效果（灼伤、冰冻、降能力、吸血）一律不生效。
现在伤害结算后也会应用官方效果表：**喷射火焰 10% 灼伤**（实测 10~12%）、**终极吸取吸血 50%**（实测回血 41 点）等。

超出「本作原有机制」的部分做了保守映射：官方 `meta.crit_rate`（暴击等级）折算为**每级 +8% 暴击率**（实测高暴击招 11% vs 普通招 4%）。

## 九、本批新增的坑

46. **「官方数据」并不等于「官方效果」**：PokéAPI 只建模了一部分机制 —— 聚气（暴击 +2）、睡觉、守住、白雾这些招的 `stat_changes` 是**空的**，效果藏在 `meta.category = unique` 里（没有结构化数据）。如果只用 `stat_changes` 生成、把「没数据的」一律当作「官方无附加效果」，这些招会直接变成废招。**教训**：拿第三方数据重建机制时，先分清「**确实没有**」和「**有但没建模**」，用 category/标记字段区分，不能只按空值判断。
47. **数据管道会因「译名变更」静默漏招**：`pokeapi-move-map.json` 是 v34 建的，用的是当时的译名（鬼面/空气斩/炼狱），而 v35c 把游戏内译名改成了可怕面孔/空气之刃/烈火深渊 —— 结果按**招名**索引的生成器完全匹配不上这三招（`可怕面孔` 会退回手工旧值「速度 −1」而不是官方的「−2」）。**教训**：凡「按显示名做 key」的数据管道，改译名时必须同步维护别名映射，否则不出错、只是静默用错数据。
48. **没被使用的字段最容易长期潜伏**：`mv.acc` 从招表建立起就存在（还有 v36c 的权威数据支撑），但**代码里从来没有读过它** —— 直到把「官方效果表」重建完、回头核对「官方还有什么没接」时才发现「所有招都是 100% 命中」。**教训**：数据字段与代码的对应关系值得定期对账（列出数据里的字段 → grep 是否被引用），尤其在做「对标官方」这类完整度要求高的任务时。
49. **验收阈值要写「相对关系」而不是「绝对差值」**：本次「命中 −2 → 命中率下降」一项第一次判失败，因为理论值 32% 与实测 33% 差 1 个百分点，而我写的是「必须小于 base−12」。**教训**：涉及随机采样的断言，用比例关系（`< base×0.8`）比用绝对差稳健。
