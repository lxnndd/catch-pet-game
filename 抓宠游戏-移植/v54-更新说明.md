### ① 你看到的「只有文本没扣血」——是这个 bug

`tickBoard()` 里中毒/灼烧的扣血写的是：

```js
p.hp = Math.max(0, p.hp - d1);      // ← 改的是 p.hp
```

但**敌方在战斗中的真值是 `B.ehp`**（伤害走 `dmgTo` → `B.ehp`），
`B.foe.hp` 只是 `initFighter` 时的初始值、之后再也没更新过 —— 于是：

```
日志：🟣 对手的 卡比兽 受到中毒侵蚀，损失 7 点 HP！
实测：B.ehp 112 → 112（血条纹丝不动）· B.foe.hp 112 → 105（改了个没人看的字段）
```

玩家侧之所以正常，是因为**玩家的真值恰好就是 `pet.hp`**（`selfHp()`/`setSelfHp()` 读写它）。

**修法**：扣血与倒下判定都按"谁的真值"分流 ——

```js
if(isSelf) setSelfHp(selfHp()-d1); else B.ehp=Math.max(0,B.ehp-d1);
```

### ② 补上灼烧的「物攻减半」

本作的灼烧原来只有每回合掉 7% 血，缺了官方那层惩罚。现在物理招在灼烧状态下伤害 ×0.5
（特殊招不受影响，同官方）。实测：撞击平均伤害 **23.3 → 11.8（0.51×）**。

### ③ 补上麻痹的「速度减半」

原来麻痹只有"35% 概率动不了"，速度毫无影响 —— 现在 `spdOf()` 里 ×0.5，
**出手顺序与技能判定都会跟着变**（速度快但被麻痹的宠会被反超）。
实测：速度 **74 → 37（0.5×）**。

### ④ 迟缓（slow）是僵尸状态

它只有名字、图标和"持续 4 回合"的定义，**没有任何招式或效果会产生它**，
`tickBoard` 里也没有它的分支 —— 也就是说游戏里永远见不到它。
这次**保留定义不删**（删了旧存档若残留该状态会显示成 `undefined`），但不再假装它存在。

## 五、本批新增的坑

71. **一套数据有两个副本时，改错一个不会有任何报错**：敌方 HP 同时存在 `B.foe.hp`（初始值）与 `B.ehp`（战斗中真值），
   掉血写到前者，**日志照样打印、函数照样返回成功**，只有血条不动。**教训**：出现「日志对、界面不对」时，
   第一反应查"这个值是不是被写到了另一个副本上"；根本解法是让真值只有一个入口（本项目玩家的 `selfHp/setSelfHp` 就是好例子）。
72. **"文本介绍了效果"不等于"实现了效果"**：灼烧的描述与日志都写了"每回合受伤"，
   而"物攻减半"这种**没有文本提示的效果**就更容易漏 —— 光看代码注释（"灼烧：每回合掉血"）也发现不了缺失。**教训**：
   做机制体检要**对照官方效果清单逐项实测**，而不是读自己的实现（本次就是靠官方清单才发现缺了两项）。
73. **僵尸状态会一直占位**：`slow` 有名字、图标、持续回合，甚至 `spdOf` 里还留着一句 `p.st.slow?0.55:1` 的遗留代码，
   但**没有任何地方会产生它**。**教训**：定期扫一遍"定义了但没人写入"的枚举值，要么补来源、要么删掉 —— 留着会误导后续开发（包括我自己）。
