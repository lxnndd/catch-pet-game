# 抓宠游戏 v95 更新说明 —— 变身后技能不再「全是已用尽」

> 线上地址：**http://47.105.123.182:8727/**
> 你的反馈：「变身后现在的技能全是用尽了」

---

## 一、原因

上一版（v93）实现变身时，复制完招式后只调了 `syncPP()`：

```js
if(_tgSp.moves.length){ _me.moves = _tgSp.moves.slice(0, SKILL_SLOTS); }
ensureMoves(_me);
syncPP(_me);          // ← 它不会为新技能建立 PP 记录
```

`syncPP()` 的作用是「按已有技能同步 PP」，而**复制来的招式在 `pet.pp` 表里根本没有键**
→ 每个技能的剩余 PP 都是 `undefined` → 界面显示**全部用尽**。

## 二、修法（两处）

**① 变身时**：直接把 PP 表重建为满

```js
_me.pp = {};
_me.moves.forEach(function(id){ if(MOVES[id]) _me.pp[id] = ppMaxOf(id); });
```

**② 还原时**：除了 PP 填满，还要把**原来的技能配置**也还回去

```js
var _origMoves = p.st.origMoves;      // 变身时一并记下原技能
if(_origMoves && _origMoves.length) p.moves = _origMoves.slice();
p.pp = {};
p.moves.forEach(function(id){ p.pp[id] = ppMaxOf(id); });
```

（原来只还原了物种，技能会一直留着对手的招。）

## 六、本批新增的坑

104. **给对象换了一批键，旧表就查不到了**：`pet.pp` 是以**技能 id 为键**的映射，
   换了技能却没重建这个映射 → 全部取到 `undefined`，表现成"PP 用尽"。
   **教训**：任何"以 id 为键的映射"，在**批量替换对象集合**时都要重建（或按新集合补齐），
   不能指望同步函数自动处理。
105. **"还原"要还原完整的状态，不只是主字段**：我第一版只还原了 `sp`（物种），
   结果技能与 PP 都留在了对手的状态。**教训**：临时变更类机制（变身/临时形态）在实现时列一张
   "改了哪些字段"的清单，还原时逐项对照 —— 否则会留下"半变身"的脏状态。
