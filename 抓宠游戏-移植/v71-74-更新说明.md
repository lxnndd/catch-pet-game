
- 不再出现「兜底 / 未实现 / 近似」这类括号说明 —— 因为 v57~v70 已把官方机制基本补齐

## 二、取消「稀有」档（v73）

### 你看到的蓝色标签是怎么来的

v43 我按**捕捉率**把宠物分成三档：`cap ≥ 100` → 普通、`25 ≤ cap < 100` → 稀有、`cap < 25` → 传说。
于是那 93 只捕捉率中等（30~90）的普通宝可梦被贴上了蓝色「稀有」标签：
**胖丁 · 吉利蛋 · 拉普拉斯 · 卡比兽 · 班基拉斯 · 烈咬陆鲨 · 象牙猪 · 巨沼怪…**

### 核查结果

| 档位 | 数量 | 与官方对照 |
|---|---|---|
| 普通（白） | 1007 | —— |
| **稀有（蓝）** | **93** | **官方传说/幻之：0 只** ← 全是按捕捉率划进来的普通宝可梦 ❌ |
| 传说（红） | 105 | 官方 `is_legendary`/`is_mythical` **零误差** ✅ |

### 修法

- SPECIES 里 93 处 `rarity:1` → `0`（**现在：普通 1100 / 稀有 0 / 传说 105**）
- `RARITY_NAME` 由 `["常见","稀有","传说"]` 改为 `["普通","普通","传说"]`
- **捕捉难度完全不受影响** —— 它一直由 `cap`（官方 `capture_rate`）决定，本来就没用稀有度
- 刷新概率也不受影响（三档权重本来就都是 1）

> 也就是说：现在只剩「**普通（白）**」与「**传说 / 幻之（红）**」两档，与官方分类一致。

## 四、本批新增的坑

85. **分了档就要能说清"依据是什么"**：我用捕捉率分三档，其中"稀有"档在官方体系里**根本不存在** ——
   官方只有 `is_legendary`/`is_mythical` 这一个特殊标记。**教训**：自定义分类若与数据源的原生分类不一致，
   早晚会与玩家认知冲突（玩家看到"稀有"会以为是官方分类）。
86. **文案会随实现过期**：v55 写的「官方机制本作未实现，这里按属性兜底」当时是对的，
   到 v70 机制补齐后就成了**错误信息**，而它不会自己消失。**教训**：临时性说明要么带版本号、
   要么在机制补齐时**同步清理**，否则会长期误导玩家。
