## 三之二、推送：`github.com` 又被阻断，改用 API

本次 `git push` 在拿凭据后直接超时：`Failed to connect to github.com:443 after 21084 ms`。
实测 `github.com` / `ssh.github.com:443` 全部不通（换 3 个 IP 也 `000`），但 **`api.github.com` 正常（200 / 0.33 s）** —— 阻断在 SNI 层，换 IP 无效。
（10-18 首次提交时 `github.com` 是通的，所以当时用普通 `git push` 完成。）

兜底：新增 `_work/tools/v96-push-api.mjs`，用 **Git Data API** 复刻本地提交 ——

```
POST /git/blobs  （逐文件 base64）
POST /git/trees  （base_tree = 远端 tree，只列 5 个变更文件）
POST /git/commits（tree + parent + message + author/committer 全照抄本地）
PATCH /git/refs/heads/main
```

结果：**远端 tree 与本地逐字节一致**（`73509fad5e65f85c0caefa2fd9e2b3c56a373015`），
但 **commit hash 不同**（本地 `a220eac…` / 远端 `e0ee577…`）—— GitHub 服务端重算 commit 对象时的细微差异，内容零差异。
等 `github.com` 恢复后 `git fetch && git reset --hard origin/main` 即可对齐（tree 相同，工作区不会变）。

脚本自带基线保护：远端 HEAD 必须等于本地父提交、且远端 tree 等于本地父 tree，否则拒绝执行，防止误覆盖别人的提交。
