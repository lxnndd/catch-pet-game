## v51 · 进化型不能早于进化等级出现（Lv9 的掘地兔）

**你看到的**：Lv9 遇到掘地兔 —— 而掘地兔是掘掘兔的进化型，**进化等级 Lv20**。

**根因**（我 v48 改等级逻辑时留的漏洞）：

```js
var sg=stageLvRange(sp,reg);
if(sg){
  var lo2=Math.max(lo,sg[0]), hi2=Math.min(hi,sg[1]);
  if(lo2<=hi2){ lo=lo2; hi=hi2; }      // ← 有交集才收窄
}                                       // ← 空集就保留 ±3 —— 问题在这
```

掘地兔的阶段区间是 **[20,100]**，而 Lv9 新手的目标区间是 [6,12] —— 两者**没有交集**，
本该「这只不该出现」，却被退回成 [6,12] → 刷出了 Lv9 的掘地兔。

**修法**：`wildLvRange()` 在无交集时**返回 null**，并在**选池子时**就把这类宠过滤掉：

```js
var _lvPool=pool.filter(function(s){ return !!wildLvRange(s,reg,_top); });
```

**实测**（脚本 `v51-verify.mjs`）：

| 场景 | 结果 |
|---|---|
| 掘地兔阶段区间 | `[20,100]` · 平原可刷 `[20,25]` |
| **Lv9 玩家 · 800 次遇敌** | 掘地兔 **0 次** · 等级 6~12 · 115 个物种 |
| 越阶段野怪（等级不在自己阶段区间内） | **0 例** |
| Lv30 玩家 · 1500 次 | 掘地兔出现 14 次，等级 **20~24** ✅ |
| Lv60 火山/荒漠/雪原 · 各 600 次 | 越阶段 **0 例** |

## v52 · 修「一个回合内敌方打两次」

**你看到的**：敌方更快 → 它先出手 → 你出手 → **它又打了一下**（全在同一回合）。

**根因**：先手分支里，`enemyStrike` 已经是**敌方本回合的行动**，但玩家出招后 `playerStrike` 结尾又调了 `enemyTurnSoon`：

```js
if(foeFirst && Math.random()<0.65){
  enemyStrike(function(){        // ← 敌方本回合行动（第 1 次）
    playerStrike(mid);           // ← 玩家行动；它结尾又 enemyTurnSoon() → 敌方第 2 次 ❌
  });
}
```

**修法**：`playerStrike(mid, noFoeTurn)` —— 这条路径传 `true`，出招后只收尾（解除忙碌、刷新按钮），
把回合交还玩家；玩家「动弹不得」的分支也一并处理。

**实测**（`v52-verify.mjs`，给 `enemyStrike`/`enemyTurn` 挂计数器）：

| 路径 | 敌方行动次数 |
|---|---|
| 敌方先手（修前） | `strike=1 + turn=1` = **2 次** ❌ |
| **敌方先手（修后）** | `strike=1 + turn=0` = **1 次** ✅ |
| 玩家先手 | `turn=1` = 1 次 ✅ |
| 连续 3 个玩家回合 | 敌方共 **3 次**（修前会到 6 次）✅ |

日志对比也很直观：
```
修前：它是先出手 → 我打 → 它又打
修后：皮卡丘 速度更快，抢在你前面出手！（摇尾巴）→ 卡比兽 的 撞击 打出 32 点伤害！
```

## v53 · 等级基准改成「当前出战宠」

**你的反馈**：遇到的都是比自己高 0~3 级的，好像没有低的。

**验证结果**（`v53-dist.mjs`）：

| 检查 | 结果 |
|---|---|
| `ri(6,12)` 本身 | 均匀（9000 次：6→1296 … 12→1316）✅ |
| **单只 Lv9 队伍** · 1000 次 | 等级 6~12 · 低于 425 / 等于 142 / 高于 433 = **0.98 : 1** ✅ 对称 |
| **出战 Lv9 + 队里一只 Lv16** · 1000 次 | 等级 **13~19** · 相对出战宠 **+4~+10，100% 偏高** ❌ |

**根因**：基准取的是 `topPartyLv()`（**队伍最高等级**），不是当前出战的宠 ——
你队里只要有一只练得高的，野怪就整体抬高，练新宠时永远在挨打。

**修法**：新增 `wildBaseLv()` = **当前场上宠的等级**（战斗外 = 首发宠），`rollEnemy` 与兜底都改用它。

**修后实测**（同一套配置）：

```
队伍最高 Lv16 · 出战 Lv9 · 等级基准 = 9 · 野怪等级 6~12
相对出战宠：-3→147 · -2→147 · -1→157 · +0→148 · +1→130 · +2→128 · +3→143
低于 451 次 · 高于 401 次 = 1.12 : 1  ← 对称了
```

> 这正好也和 v49 的「全队共享经验」配套：练新宠时野怪跟着**新宠**走，而不是被队里的高等级宠拖着。

## 本批新增的坑

68. **「无交集就退回默认值」是危险的兜底**：v48 里「阶段区间与目标区间无交集 → 退回目标区间」，
   看起来是"永不失败"的写法，实际是把「这只不该出现」悄悄改成了「那就随便给个等级」，
   于是进化型跑到进化等级之前。**教训**：当"约束不满足"意味着**前提错误**（这只宠不该在这里）时，
   应当返回失败/null 让调用方换一个，而不是给一个看似合理的默认值。
69. **速度先手分支要分清「敌方本回合行动」与「敌方回合」**：`enemyStrike` 与 `enemyTurn` 名字相近、
   都会让敌方出招，但前者是"替它打完本回合"，后者是"推进到敌方回合" —— 先手路径里两者都调，
   就是同一回合打两次。**教训**：这类"回合推进"的函数最好用参数或状态机显式表达「本回合是否已行动」，
   不要靠调用者记住。
70. **「基准取谁」会被玩家立刻感知**：`topPartyLv()`（队伍最高）与出战宠等级在代码里只差一行，
   但对玩家体验是"练新宠时永远挨打" vs "野怪跟着当前宠走"。**教训**：凡是"跟随玩家强度"的数值，
   想清楚是跟**账号实力**还是跟**当前出场单位** —— 有养成/换宠机制的游戏里，后者通常才是玩家期望的。
