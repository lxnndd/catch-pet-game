## 三、修「四天王为什么有 5 位」

**根因**：`REAL_E4` 数组里存的是 **4 位四天王 + 1 位冠军（青绿）= 5 条**，而文案直接用了数组长度：

```js
_pb.textContent = "⚔️ 挑战四天王（第 " + (LEAGUE_IDX+1) + " 位 / 共 " + N + " 位）";   // N = 5 ❌
```

**现在**把两者分开计数：

| 进度 | 按钮 | 说明文案 |
|---|---|---|
| 第 1~4 位 | ⚔️ 挑战四天王（第 N 位 / **共 4 位**） | 已击败四天王 N / 4 位 |
| 第 5 位 | ⚔️ **挑战冠军（青绿）** | 四天王已全部击败（4 / 4）——下一位就是冠军「青绿」，打赢他就通关！ |
| 已夺冠 | 🔁 重新挑战联盟 | 🏆 你已击败四天王与冠军 |

## 六、本批新增的坑

56. **「同一句话里的两个数字口径不同」最容易出这种 bug**：`REAL_E4.length` 是「四天王 + 冠军」的总数，而文案里写的是「挑战**四天王**（共 N 位）」—— 分母的语义被悄悄换了。**教训**：凡是"第 N 位 / 共 M 位"的文案，N 和 M 必须来自**同一个集合**；集合里混了不同类别（选手 vs 裁判）时，先拆成两个计数再拼文案。
57. **增量的功能会留下"旧入口"**：徽章面板的「去挑战」是早期为了好测试加的便捷入口，功能做完整之后它就变成了"破坏设计意图的旁路"（可以隔空打馆）。**教训**：给测试加的便捷入口要标记清楚，功能定型时回头清理 —— 否则它会一直留在那里改变游戏体验。
