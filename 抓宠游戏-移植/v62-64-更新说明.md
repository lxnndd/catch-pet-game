## 一、你说的对：增强拳当时确实没修 —— 因为我的写入脚本静默失败了

上一版我改了生成器（用 `category` 判能力变化方向）并跑了 `--apply`，控制台还打印了「增强拳 → {buff:{atk:1}}」，
**但文件里其实还是旧的**。根因：

```js
// 我的解析器 lit() 只支持 [ 和 { 开头的变量
const open = text[j], close = open === '[' ? ']' : '}';
```

而 `POKE_MOVES` 是 **IIFE**（`var POKE_MOVES=(function(){…})();`）—— 以 `(` 开头，
于是第二次 `--apply` 时括号配对错乱、**整个写入被跳过**，而脚本既不报错也不提示失败。
（第一次 `--apply` 时 `POKE_MOVES` 还不存在，走的是另一条分支，所以那次的 volatile/连击数据是写进去的。）

**修法**：`lit()` 支持 `(`；并在验收里**读文件确认真值**，不再只信控制台输出。

**修好后实测**：

```
增强拳：MOVE_FX = {"buff":{"atk":1}} · 出招后 我方攻击档 0 → 1 · 对手攻击档 0 ✅
（修复前：MOVE_FX = {"debuff":{"atk":-1}}，即把 +1 加给了对手）
```

连带 16 条方向错误的招**这次真正生效**：近身战/臂锤/蛮力/飞叶风暴/过热/金属爪/彗星拳/钢翼/
原始之力/奇异之风/银色旋风/充电光束/蓄能焰袭/高速旋转/耕地。

### 过程中修掉的 3 个根因（都是"机制写了但不生效"）

1. **`power = 0` 的攻击招被当成变化技** —— 判断条件是 `mv.cat === "变化" || !mv.power`，
   于是「蛮干 / 地球上投 / 地裂」全走进了变化技分支，特殊伤害根本没机会执行。现在**只看分类**。
2. **特殊伤害被 85% 上限削平** —— 蛮干只能把对手拉到 85% 处、一击必杀秒不掉。现在固定伤害 /
   蛮干 / 一击必杀三类**不受该上限约束**（它们的伤害由规则直接决定）。
3. **一击必杀的成功率被算了两遍** —— 官方 `accuracy = 30` 本身就是它的成功率，
   我又在 ohko 分支判了一次 30%，相乘变成 **9%**。现在 ohko 招跳过命中判定。

## 六、本批新增的坑

77. **「脚本打印了成功」不等于「文件真的改了」**：`--apply` 打印了生成结果、却没打印「已写入」——
   我当时用 `Select-Object -First 5` 截断了输出，恰好把失败信号截掉了；而解析器的括号错配是**静默跳过**而非抛错。
   **教训**：批处理脚本必须**以"落地校验"收尾**（回读文件、grep 关键值），并且不要把输出的尾部截掉 ——
   失败信息往往在最后一行。
78. **`||` 拼出来的判定会悄悄改变分支**：`mv.cat === "变化" || !mv.power` 本意是"有些变化技带残留威力"，
   实际把**威力为 0 的攻击招**全推进了变化技分支（蛮干/地球上投/地裂）。**教训**：分支条件里混入"补充性"
   的或条件时，要逐个想清楚"哪些正常数据会被它意外命中"。
79. **"上限/削峰"机制会吃掉特殊规则**：85% 伤害上限让蛮干拉不平、一击必杀秒不掉。
   **教训**：凡是"由规则直接决定"的数值（固定伤害、HP 拉平、必杀），都要显式排除在通用上限之外。
