# 抓宠游戏 v87~v88 更新说明 —— 技能栏没满时，从左边拖到空白处 = 直接添加

> 线上地址：**http://47.105.123.182:8727/**
> 你的反馈：「技能调整还是有问题，现在只有两个技能，但是左边拖不过来」

---

## 一、原因

上一版（v82）我修的是「左池里混着已带的技能」这个 bug。但**还有一个没覆盖到的情况**：

拖拽落点的判定只认**技能卡**：

```js
var card = el.closest(".learn-card[data-skill]");   // 只找卡片
if(!card) return;                                   // 找不到 → 直接放弃
```

而放下的逻辑也只支持**替换**：

```js
if(fromSide==="pool" && toSide==="cur"){
  var i = pet.moves.indexOf(toId);   // 必须落到某个已有技能上
  if(i < 0) return;
  pet.moves[i] = fromId;
}
```

所以当宠物**只有 2 个技能（上限 4）**、你想「再加一个」时：
把左边的招拖到右侧**空白区域** → 那里没有卡片 → `return` → **界面毫无反应**。
（只有拖到那 2 个已有技能上才能生效 —— 但那是"替换"，不是"添加"。）

> 有意思的是：**点击流程**（`doLearn`）早就支持"没满就直接加上"，
> 只有**拖拽**这条路径漏了 —— 同一功能的两条入口行为不一致。

## 二、修法（4 处）

1. **落点识别** `_hiAt()`：找不到卡片时，把右侧容器 `#learn-cur` 也视为合法落点
2. **松手处理** `onUp`：容器 → `side="cur"`、`skillId=null`
3. **放下逻辑** `applySkillDrop()`：`toId` 为空时
   - 技能没满 → **直接 push**（添加）
   - 已带着 → 提示「这个技能已经带着了～」
   - 栏位满 → 提示「技能栏满了（4 个），拖到某个旧技能上替换它」
4. **样式**：`#learn-cur` 给 190px 最小高度 + 拖入时蓝色虚线高亮，保证空白区好落

## 三、实测（`v88-pool2.mjs`，6/6）

```
① 只有 2 个技能时拖到空白
   拖之前（2 个）：撞击 / 叫声
   拖之后（3 个）：撞击 / 叫声 / 藤鞭        ✅ 成功添加

② 技能栏满（4 个）时拖到空白
   4 个 → 4 个                              ✅ 不硬塞，提示去替换

③ 拖到已有技能上
   用「寄生种子」替换掉「撞击」               ✅ 原功能保留

④ 落点识别
   在右侧空白处取点：命中 learn-cur · min-height 190px · 高亮 ✅
```

## 四、现在的完整交互

| 操作 | 行为 |
|---|---|
| 左 → 右（拖到**已有技能卡**上） | 替换掉那个技能 |
| 左 → 右（拖到**右侧空白**，技能没满） | **直接添加**（本次修复） |
| 左 → 右（拖到空白，但栏位已满） | 提示去替换 |
| 右 → 左（拖到左池任何位置） | 卸下这个技能 |
| 右 → 右（技能卡之间） | 互换位置 |
| 点左边技能 → 点右边技能 | 也是替换（点击路径） |

## 六、本批新增的坑

97. **同一功能的两条入口要一起改**：点击路径（`doLearn`）早就支持"没满就添加"，
   而拖拽路径（`applySkillDrop`）只支持"替换" —— 我上一版修拖拽时只盯着"池子里混了已带的招"，
   没想到**没满时的添加**这条分支在拖拽里压根不存在。**教训**：修交互 bug 时，先把
   "同一件事有几种操作方式"列出来（点击/拖拽/快捷键…），逐个确认行为一致。
98. **落点判定只认"有内容的元素"是常见盲区**：拖拽实现里 `closest('.learn-card[data-skill]')`
   天然排除了空白容器，于是**"拖到空白处"这个动作在代码里不存在**。
   **教训**：做拖放时，容器本身也要注册为 drop zone（并给出视觉反馈），不能只依赖里面的条目。
