## 二、升级速度：改成宝可梦官方六种经验曲线

### 问题（你报的「升级太快」）

旧曲线是一行 `expNeed(lv) = 10 + lv*2`（**线性**），而经验来源是「对手血量上限」：

| | 旧（线性） | 官方「较快组」 |
|---|---|---|
| Lv1→2 | 12 | 8 |
| Lv25→26 | 60 | **1951** |
| Lv50→51 | 110 | **7651** |
| Lv99→100 | 208 | **29701** |
| 升到 Lv100 累计 | **10,890** | **1,000,000** |

低级段两者接近、**高级段差近百倍**，所以中后期几乎一场一级。

### 改法

1. **曲线**：每只宠用它**自己在官方数据里的曲线**（PokéAPI `growth_rate`，注入 `SPECIES.growth`），六种全部实现：
   `fast 0.8n³` · `medium(较快) n³` · `slow 1.25n³` · `medium-slow 1.2n³-15n²+100n-140` · `slow-then-very-fast`(最快,分段) · `fast-then-very-slow`(最慢,分段)。
   本作 1025 只宝可梦的曲线分布：**medium 399 · medium-slow 261 · slow 255 · fast 67 · slow-then-very-fast 29 · fast-then-very-slow 14**。
   洛克王国没有官方曲线 → 统一按 `medium`，基础经验值 b 用「种族值总和 ÷ 3」近似。
2. **给经验**：改用官方第七世代公式（原来是血量上限）

   ```
   exp = ( b × L/5 × s × k × ((2L+10)/(L+Lp+10))^2.5 + 1 ) × t × e × f × v × p
   ```
   本作取：`b` = 该物种的官方 base_experience，`L` = 对手等级，`Lp` = 我方等级，其余系数无对应机制取 1；
   **训练师/道馆战额外 ×1.5**（官方第七世代已取消，本作保留更好玩）。

### 改后手感（实测口径：打一只同级、b=100 的野生宠）

| 等级 | 本级所需经验 | 打一只得 | 需要只数 |
|---|---|---|---|
| Lv5 | 91 | 101 | **0.9** |
| Lv20 | 1261 | 401 | **3.1** |
| Lv30 | 2791 | 601 | **4.6** |
| Lv50 | 7651 | 1001 | **7.6** |
| Lv70 | 14911 | 1401 | **10.6** |
| Lv99 | 29701 | 1981 | **15.0** |

低级段依旧很快（这是官方本身的手感），中后期明显需要经营；**打高等级宠或有 b 值更大的宠收益更高**（公式里的 b 与等级差都在起作用）。

## 三、战斗数值公式：能力值改官方 · 能力等级扩六项 · 修掉防御侧符号错误

### 问题（你说的「种族值和左边的数值相差有点大」）

旧公式 `floor((2×种族值 + 15) × (1 + 等级/25))` 的量级约为官方的 **5 倍**：

| | 旧 | 官方（个体31·努力0） |
|---|---|---|
| 种族 100 · Lv50 | **645** | **120** |
| 种族 100 · Lv100 | **1075** | **236** |

所以面板上「实际值 645（种族 100）」看着完全不搭。

### 改法

- **能力值**：官方公式 `floor((2×种族值 + 个体值) × 等级 / 100) + 5`，个体值取官方满值 **31**（原为 15）。
- **血量**：官方公式 `floor((2×种族值 + 个体值) × 等级/100) + 等级 + 10`（原实现漏了个体项），**保留 `HP_C = 12` 的基数补给**（v15 的结论：官方公式 1 级只有 11~12 血，会被一击必杀）。
- 详情面板与战斗用**同一个函数**（`statVal` / `statValOf`），不会再出现「面板数字与实战不符」。

**面板实测（皮卡丘 Lv50，个体31）**：

```
❤️ HP    122 / 122  （种族 35）    ← 官方 110 + HP_C 的 12
⚔️ 攻击   75        （种族 55）    ← 与 wiki 完全一致
🛡️ 防御   60        （种族 40）
🔥 特攻   70        （种族 50）
💠 特防   70        （种族 50）
💨 速度  110        （种族 90）
✨ 经验值 2678 / 7651（还差 4973）
```

### 为什么改了量级却**不影响战斗节奏**

伤害公式里用的是**攻/防比值**（`clamp(0.9,1.6) × DMG_K`），速度只做「谁大谁先手」的相对比较 —— 两者都是**相对量**，整体缩放不影响结果。血量公式本来就接近官方，这次只补了个体项（Lv50 大约 +13%），回归实测战斗回合数仍在原区间：**20 级同级 3.4 回合 · 56 级同级 2.2 回合**。

### 顺带修掉：防御侧系数被写成「乘法」，方向整个反了

伤害公式里有一处从 v14 定标起就存在的符号错误：

```js
/* 改前 */  ... * stag * defT.def * dstag * ...
/* 改后 */  ... * stag * ... / (defT.def * dstag)
```

`defT.def` 是**防御方性格的防御修正**、`dstag` 是**防御方防御/特防的能力等级**。把这两项乘进伤害，等于说：

| 情况 | 改前的实际效果 | 改后 |
|---|---|---|
| 对手防御性格 +10% | 你打它**更疼** 10% | 你打它**少**约 9% |
| 自己用「铁壁」（防御 +2） | 自己**更脆**（挨打 ×1.6） | 挨打 ÷1.6 |
| 自己用「刺耳声」降对手防御 | 自己伤害**变低**（×0.64） | 伤害 ×1.6 |

因为性格修正幅度小（0.85~1.10）、且历次平衡测试都在「无能力等级」条件下做，这个错误一直没被触发 —— 是这次做能力等级六项、用真实 `applyMove` 跑「降对手防御后伤害本应变高」的对照矩阵才暴露出来。

### 能力等级扩成官方六项

原来只有 `atk / def / spd / crit` 四项，官方的「特攻 +2」「特防 −2」无处安放 —— 那些招被塞进 `atk`/`def` 档，**数值上歪打正着，但作用面比官方宽**（物理与特殊两侧一起受影响），长按浮层还会把「诡计」显示成「自身 攻击 +2」。

现在 `STAGE_KEYS = 攻 / 防 / 特攻 / 特防 / 速度 / 暴击`，伤害公式按招式分类取档：

```js
var _atkKey = _isSpecial ? "spa"   : "atk";     // 特殊招读特攻档
var _defKey = _isSpecial ? "spDef" : "def";     // 特殊招读特防档
```

受影响招式已改到正确档位：**诡计 / 阴谋 → 特攻 +2** · **冥想 → 特攻 +1、特防 +1** · **生长 → 攻击 +1、特攻 +1** · **宇宙力量 → 防御 +1、特防 +1** · **金属音 → 特防 −2** · **溶解液 → 特防 −1（并保留 30% 中毒）**。旧存档只有四项档位，`initSt()` 会自动补 0，不影响读档。

实测对照矩阵（真实 `applyMove`，各取样 24 次，对手用血厚的卡比兽以避免顶到 85% 上限）：

| 条件 | 物理招（劈开） | 特殊招（喷射火焰） |
|---|---|---|
| 自身 攻击 +2 | **×1.57** | ×0.96（不受影响） |
| 自身 特攻 +2 | ×1.08（不受影响） | **×1.56** |
| 对手 防御 −2 | **×1.54** | ×1.01 |
| 对手 特防 −2 | ×0.96 | **×1.58** |

> 注：官方还有「命中 / 闪避」两档，本作没有这两个机制，相应的招（影子分身、甜甜香气等）仍映射到「速度」档；另外几处数值与官方有差（如「萤火」官方是特攻 +3、本作 +1；「可怕面孔」官方降速度 2、本作 1），本次只改档位归属、没动数值，需要的话再说。

## 七、新增的坑

37. **大段替换公式区，很容易连带删掉紧邻的小工具函数**：本次改能力值公式时，一次性替换那 9 行，把夹在中间的 `statOf()` 定义一起删掉了（它被 `statVal` / 详情面板 / 数据脚本到处引用）。`catch-pet-syntax.mjs` 与 `catch-pet-dupcheck.mjs` **都没能报出这个问题**（语法合法、无重复），是浏览器的实测验收才暴露的。**教训**：改公式块要**逐函数替换**，改完必须跑一次浏览器实测（不是只看静态体检）。
38. **曲线和给经验必须成对改**：经验需求换成三次方、给经验却还是「血量上限」（线性）的话，高等级要打几百场；反过来先改给经验、不改曲线，则会瞬间满级。**任何一条改动能曲线的改动，都要同时算「打一只同级怪能升几级」**。
39. **经验曲线不能只看公式、还要看分段**：官方六种曲线里「最快组」「最慢组」是分段函数（各自 3~4 段），照抄多项式会把 Lv1~15 算错（例如较慢组在 Lv1 会算出 −54）。本作把 `expTotal(1)` 特判为 0，并用官方累积经验表逐点对账（`v41-verify.mjs` 24 项）。
40. **官方量级与自研量级混用，面板数字就会「看着不搭」**：本作血量很早就用了官方公式，能力值却是自研的 5 倍量级 —— 单看战斗没问题，一显示到面板就露馅。**教训**：同一套属性只要有一项接官方公式，其余项也应当对齐口径。
41. **一个函数的「补全」语义会和后来的「反向操作」对撞**：`ensureMoves()`（v17）的职责是「保证技能齐备」，v31 却加了「拖回左边卸下技能」—— 两者共存时，前者「不足 4 个就补满」会把后者的结果静默撤销。更隐蔽的是 `applySkillDrop()` 在**判断保护条件之前**就调了它，于是连「只剩 1 个不许再卸」的保护也一起失效（削到 1 个会被补成 4 个再卸掉一个，反而变成 3 个）。**教训**：给某个对象加「反向操作」（卸下 / 删除 / 减到更少）时，先 grep 所有会在同一对象上「补全 / 自动填充」的函数，确认它们的触发条件不会把反向操作吃回去。
42. **验收脚本自己会引入随机失败**：`v41-accept` 的「差 1 点经验不升级」在本地通过、在公网失败 —— 因为 `newPet()` 随机分配特性，而「好奇」经验 ×1.35、「慵懒」×0.7，随机到它们就会让经验断言失效。**教训**：凡断言涉及数值，脚本里要把随机源（特性、个体、概率）钉死成确定值。
43. **「提高防御反而更脆」——乘除方向写错不会报错，只会静静地把机制反过来**：伤害公式里 `defT.def * dstag`（防御方性格修正 × 防御方能力等级）本该在**分母**，却被写成乘数，于是「对手防御越高你打它越疼」「铁壁让自己更脆」「刺耳声让自己的伤害变低」。它从 v14 定标起就在，历次平衡测试都没碰到 —— 因为那些测试都是**在无能力等级的裸装条件下**跑的。**教训**：凡「对方某属性越高 → 我输出越低」的关系，写公式时先确认系数在分子还是分母；并且**平衡回归要覆盖带增减益的场景**。
44. **验收脚本自己会污染被测状态**：`v41-stages-verify` 最初每次取样都调 `reset()`，而 `reset()` 里的 `clearStatus()` 正好把刚设好的能力等级清掉，于是整张对照矩阵呈现出「所有档位都无效」的假象。**教训**：测量类脚本要明确「清空 → 施加 → 回血 → 测量」的执行顺序，别把清空与施加放在同一层。
