# 抓宠游戏 v22 更新说明（卡顿根治：HTML 7.3MB → 732KB）

> 线上地址：**http://47.105.123.182:8727/**

---

## 一、「很卡」的真实原因

先说结论：**不是代码慢，是页面太大**。

我先逐项测了代码性能（无头浏览器实测）：

| 项目 | 耗时 | 结论 |
|---|---|---|
| 加载到可玩 | 0.6 秒 | 不慢 |
| `genMap()` 生成 87,500 格地图 | 0.44 秒 | 不慢 |
| `draw()` 每帧 | 0.16 ms | 极快（视口裁剪） |
| `updateHUD()` | 0.00 ms | 可以忽略 |
| `save()` 存档（含 11 万字符地图） | 0.9 ms | 可以忽略 |
| 连续走 30 步 | 0.00 秒 | 不慢 |

**真正的问题**：整个游戏被打包成**一个 7.3 MB 的 HTML**，其中 **6.5 MB 是 1205 张宠物头像的 base64 内联数据**。
手机浏览器要先把 7.3 MB 文本下载完、再解析、再把 6.5 MB 的 base64 逐张解码成图片 —— 这个过程在手机上要好几秒，期间页面看起来就是"卡住 / 进不去"。

## 二、修复：头像改为外置按需加载

- 头像不再内联进 HTML，改成独立文件 `avatars/pk-001.webp`（128×128 WebP，平均 4KB）
- `avatarURL()` 从"拼 data URL"改成"返回文件路径"，浏览器按需加载 + 自动缓存

**效果对比**：

| | 优化前 | **优化后** |
|---|---|---|
| HTML 体积 | **7.10 MB** | **0.72 MB**（↓ 90%） |
| 公网首页传输 | 7.3 MB | **773 KB · 183 ms** |
| 公网加载到可玩 | 手机上数秒（以为进不去） | **0.69 秒** |
| 单张头像 | 内联在 HTML 里 | 独立 4 KB · 42 ms（浏览器会缓存） |

验证：头像能在游戏里正常显示（实测 `avatars/pk-037.webp` 加载成功、128×128、游戏内头像渲染正常）、零异常。

## 三、一个需要你知道的取舍

**头像外置后，游戏不再是"单个 HTML 文件"**：
- 现在部署到服务器上是一整套（`index.html` + `avatars/` 目录 1285 张图），联网访问完全正常，而且更快
- 但如果你要**把这个游戏拷给别人、或者离线打开单个 HTML**，头像就显示不出来（因为找不到 `avatars/` 目录）

如果你更看重"单文件能离线分享"，我可以做一个折中方案：**保留单文件版本（内联头像）作为分发用，服务器上用轻量版**（两套并存，互不影响）。需要的话说一声。

## 四、顺带说明上次「进不去」

上次你说的"进不去"，根因就是同一个：7.3 MB 页面在手机上加载太慢，等了几秒没反应就以为坏了。现在 0.7 秒就能进。

（另外我按你的要求核对过：这个"进不去"**不是** v21 改城镇画面导致的脚本错误 —— 我抓了公网控制台的异常，是 **0 条**。）
