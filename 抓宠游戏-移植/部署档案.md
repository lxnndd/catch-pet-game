## 七、已知坑

1. **同一个函数被定义两次 = 前一次白改**：本轮 `enemyFainted` / `onSelfFaint` / `wipedRetreat` 各存在新旧两份定义，后定义的旧版把新逻辑整个覆盖，表现为「训练师打倒一只后走的是野生结算、直接结束战斗」。改动大段逻辑后用 `catch-pet-dupcheck.mjs` 扫一遍，必查。
2. **`byId()` 只接受字符串 id**：`byId(SPECIES条目)` 恒返回 null。跨函数传物种时统一走 `resolveSp()`（字符串/对象都吃）。历史上 `beginTrainerBattle` 把对象又交给 `byId` 一次，直接导致开战崩溃。
3. **CDP 验收务必 `Network.setCacheDisabled` + URL 加时间戳**：否则新标签页可能命中 HTTP 缓存，出现「服务端已是新版、浏览器仍在跑旧函数」的假故障，极易误判。
4. **systemd unit 必须 base64 传输**：用 `printf '%s'` 配合 JSON 转义会把真换行写成字面 `\n`，systemd 报 `Bad message`。且 `Description` 保持纯 ASCII（中文描述在非 UTF-8 locale 下会报错）。
5. **新端口一定要放行云防火墙**：服务器 ufw/iptables 都是放开的，拦住的是阿里云轻量控制台的「防火墙」（该产品没有「安全组」这个概念）。
6. **无头 Edge 的截图偏暗**：无 GPU 导致渐变渲染偏暗，真机浏览器上是正常绿色，别被截图误导。
7. **本机外网请求一律用 node**：PowerShell 的 `Invoke-WebRequest` 对部分站点会 SSL 失败，`node fetch` 正常。
8. **中文文本处理用 node 脚本写文件再读**：PowerShell 内联 `node -e` 处理中文正则/转义极易 ParseError 与乱码；长脚本一律先 write 成 .mjs 再执行。
9. **地图扩大后旧存档会重开地图**：`mapStr.length === MW*MH` 校验失败即重新 `genMap()`，玩家坐标若越界或落在障碍上会被拉回出生点 `(36,28)`——属预期降级，不是 bug。
10. **注入数据块绝不能用 `slice(0, indexOf(A)) + 新数据 + slice(indexOf(B))` 跨段替换**：这会把 A 与 B 之间的全部代码一起删掉。v14 注入 CHART 时就因为终点写成 `var MOVES={`，把夹在中间的 `typeEdge / typesOf / eff / effText / typeText / typeClass` 六个函数整段吞掉，表现为「页面能打开、点进草丛就崩、战斗打不开」。现在 `build-v14.mjs` 改成「按变量块起止逐块替换 + 区间内不得出现 `function` 定义 + 注入后自检关键函数是否还在」三重保险；改动数据注入后**必须**跑一遍 `catch-pet-syntax.mjs`（它会报「可疑的未声明函数调用」，v14 就是靠它发现 `typeEdge` 失踪的）。
11. **判断「基础形态」不能用 `s.ev`**：`ev` 标记的是「它有进化目标」，御三家这类基础形态同样带 `ev:true`。早前野生遇敌池用 `!s.ev` 过滤，等于把所有能进化的宠（含全部御三家）排除在野外之外。正确判据是 `isEvolvedForm(sp)`——「没有任何 EVO 指向它」，函数内用 `evolvedIds` 缓存，避免每次遇敌都 O(n) 扫 EVO 表。
12. **无头验收要自己准备干净状态**：无头 profile 会残留 localStorage 存档 —— 有队伍时点「进入草丛」会直接进世界、跳过初始伙伴屏，导致相关断言误判失败。`accept-v14.mjs` 第 4 组现在先 `localStorage.removeItem(SAVE_KEY)` 再重载页面，保证每次都真的走一遍选伙伴流程。

### v41 新增九条坑

37. **大段替换公式区，很容易连带删掉紧邻的小工具函数**：v41 改能力值公式时一次性替换那 9 行，把夹在中间的 `statOf()` 定义一起删掉了（`statVal`、详情面板、数据脚本到处都在用它）。而 `catch-pet-syntax.mjs` 与 `catch-pet-dupcheck.mjs` **都没报出来**（语法合法、无重复定义），是浏览器的实测验收才暴露。**教训**：改公式块要**逐函数替换**，改完必须跑一次浏览器实测，不能只看静态体检。
38. **经验曲线与「给经验公式」必须成对改**：需求换成三次方、给经验还是「血量上限」（线性）→ 高等级要打几百场；反过来先改给经验不改曲线 → 瞬间满级。**任何改动能曲线的改动，都要同时算「打一只同级怪能升几级」**（`v41-verify.mjs` 第 5 节就是这张表）。
39. **官方曲线里有分段函数，照抄多项式会在低等级算错**：六种曲线中「最快组」「最慢组」各是 3~4 段分段函数（例如较慢组 Lv1 的多项式会给 −54）。本作把 `expTotal(1)` 特判为 0，并用官方累积经验表**逐点对账**（24 项）。
40. **官方量级与自研量级混用，面板数字就会「看着不搭」**：本作血量很早就用了官方公式，能力值却是自研的 5 倍量级 —— 单看战斗没问题，一显示到面板就露馅（种族 100 的宠 Lv50 显示 645）。**教训**：同一套属性只要有一项接官方公式，其余项也应对齐口径。
41. **一个函数的「补全」语义会和后来的「反向操作」对撞**：`ensureMoves()`（v17，职责是"保证技能齐备"）里有「不足 4 个就从池子补满」，而 v31 加了「拖回左边卸下技能」—— 于是卸下看似生效，**下次打开面板就被补回第 4 个**；`applySkillDrop()` 还在**判断保护条件之前**先调了它，导致「只剩 1 个不许再卸」的保护也失效（削到 1 个会被补成 4 个再卸掉一个，反而变成 3 个）。**教训**：给某对象加「反向操作」（卸下 / 删除 / 减到更少）时，先 `grep` 所有会在同一对象上「补全 / 自动填充」的函数，确认它们不会把反向操作吃回去。
42. **验收脚本自己会引入随机失败**：`v41-accept` 的「差 1 点经验不升级」本地通过、公网失败 —— 因为 `newPet()` 随机分配特性，而「好奇」经验 ×1.35、「慵懒」×0.7，随机到它们经验断言就废。**教训**：断言一旦涉及数值，脚本里要把随机源（特性 / 个体 / 概率）钉成确定值。
43. **静态体检查不出「删错函数」**：v41 改能力值公式时连带删掉了 `statOf()`，而 `catch-pet-syntax.mjs` 与 `catch-pet-dupcheck.mjs` 都没报（语法合法、无重复定义），是浏览器验收才暴露。**教训**：改公式/数据块后，静态体检只能算进场券，**必须再跑一次浏览器实测**。
44. **「提高防御反而更脆」——乘除方向写错不会报错，只会静静地把机制反过来**：伤害公式里 `defT.def * dstag`（防御方性格修正 × 防御方防御/特防能力等级）本该在**分母**，却被写成乘数 —— 于是「对手防御越高你打它越疼」「铁壁让自己更脆」「刺耳声让自己的伤害变低」。它从 v14 定标起就在，历次平衡测试都没碰到，因为那些测试全是**在无能力等级的裸装条件下**跑的。**教训**：凡「对方某属性越高 → 我输出越低」的关系，写公式时先确认系数在分子还是分母；平衡回归必须覆盖**带增减益**的场景。

### v42 新增四条坑

46. **「官方数据」不等于「官方效果」**：PokéAPI 只建模了一部分机制 —— 聚气（暴击 +2）、睡觉、守住、白雾这些招的 `stat_changes` 是**空的**，效果藏在 `meta.category = unique` 里（没有结构化数据）。如果只用 `stat_changes` 生成、并把「没有数据」一律当成「官方无附加效果」，这些招会直接变成废招。**教训**：拿第三方数据重建机制时，先分清「**确实没有**」与「**有但没建模**」，用 category 之类的标记字段区分，不能只按空值判断。
47. **数据管道会因「译名变更」静默漏招**：`pokeapi-move-map.json` 是 v34 建的，用的是当时的译名（鬼面/空气斩/炼狱），而 v35c 把游戏内译名改成了可怕面孔/空气之刃/烈火深渊 —— 于是按**招名**索引的生成器完全匹配不上这三招（`可怕面孔` 会退回手工旧值「速度 −1」而不是官方的「−2」）。**教训**：凡「按显示名做 key」的数据管道，改译名时必须同步维护别名映射，否则不报错、只是静默用错数据。
48. **没被使用的字段最容易长期潜伏**：`mv.acc`（招式命中率）从招表建立起就存在，但**代码里从来没读过它** —— 等于所有招式都是 100% 命中，直到重建官方效果表、回头核对「官方还有什么没接」时才发现。**教训**：定期对账「数据字段 → 代码是否引用」，做「对标官方」这类完整度要求高的任务时尤其必要。
49. **验收阈值要写「相对关系」而不是「绝对差值」**：本次「命中 −2 → 命中率下降」一次判失败，因为理论 32% 与实测 33% 差 1 个百分点，而断言写的是「必须小于 base−12」。**教训**：涉及随机采样的断言用比例（`< base×0.8`）比绝对差稳健。

### v43 新增三条坑

50. **用户报的数值要先复算，别照着改**：用户说「神兽满血抓取概率 0.4%」，实际复算 —— 改前的自研公式给的是 **4.5%**，官方是 **1.57%**，三个数都不一样。**教训**：用户给的数字可能来自记忆或别处，先把自己的公式复算一遍、再和官方对账，然后照**官方**实现，而不是往用户说的数字上调。
