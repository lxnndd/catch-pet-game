# 抓宠游戏 · 部署与运维指南

## 一、访问地址与服务状态

| 用途 | 地址 |
|---|---|
| **公网玩家入口** | http://47.105.123.182:8727/ |
| 服务器本机自测 | http://127.0.0.1:8727/ |
| 健康检查 | http://47.105.123.182:8727/health |

- **端口**：`8727`（需在阿里云轻量控制台「防火墙」放行 TCP `8727`，系统自带 ufw/iptables 默认全放行）
- **服务名**：`catch-pet.service`（开机自启，`active + enabled`）
- **静态服务版本**：`app/server.mjs` v1.0.0（零依赖 Node 内置模块，支持 `.html`/文本资源按 `mtimeMs` 自动 **Brotli / Gzip** 内存缓存压缩，HTML 响应 `Cache-Control: no-cache` 保证刷新即得新版，静态立绘 `max-age=86400`）

## 三、本地开发与一键部署

### 1. 本地启动与静态体检

```bash
# 在项目根目录（抓宠游戏/）下执行：
node app/server.mjs
# 环境变量可覆盖：PORT=8727  ROOT=./app/site  LOG_DIR=./app/logs

# 改完 app/site/index.html 后必跑的三项静态体检：
node tools/catch-pet-syntax.mjs
node tools/catch-pet-dupcheck.mjs
node tools/catch-pet-check.mjs
```

### 2. 一键部署到线上服务器

```bash
node tools/catch-pet-deploy.mjs
```

脚本流程（依赖 `tools/deploy-config.json` 与 `tools/node_modules/ssh2`）：
1. 本地 `tar` 打包 `app/server.mjs` 与 `app/site` 为临时压缩包 `tools/_deploy.tgz`；
2. SFTP 上传至 `/tmp/catch-pet.tgz` 并原子解压覆盖 `/opt/catch-pet/app`；
3. Base64 写入 `/etc/catch-pet/catch-pet.service`（`Description` 保持纯 ASCII）并 `systemctl restart catch-pet`；
4. 本机 `curl` 探活 `/health` 与首页状态码后清理本地压缩包。

### 3. 常用服务器运维命令

```bash
systemctl status catch-pet        # 查看服务状态
systemctl restart catch-pet       # 重启服务
journalctl -u catch-pet -n 50     # 查看 systemd 日志
tail -f /opt/catch-pet/log/*.log  # 查看访问日志
ss -lntp | grep 8727              # 确认端口监听
```

## 四、GitHub 仓库与推送

- **公开仓库**：<https://github.com/lxnndd/catch-pet-game>（分支 `main`）
- **常规推送**：`git add -A && git commit -m "..." && git push`
- **兜底推送（SNI 阻断时）**：当 `github.com:443` 超时但 `api.github.com` 正常时，可使用 `tools/v96-push-api.mjs` 通过 Git Data API 将本地最新提交复刻推送到 `main`：
  ```bash
  node tools/v96-push-api.mjs          # 仅校验基线与差异文件
  node tools/v96-push-api.mjs --apply  # 真正提交到远端
  ```
- **Windows 环境注意**：若遇到 `detected dubious ownership`，执行 `git config --global --add safe.directory 'C:/Users/10709/Desktop/AI/抓宠游戏'`。
